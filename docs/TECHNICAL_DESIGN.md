# 需求分析与技术选择

研究日期：2026-11-06。当前默认目标是用户仅上传截图，自动替换右侧自己的头像，保留左侧内容、尺寸与版式，尤其是圆角及抗锯齿边缘。模板检索作为可选兼容模式保留。

## 当前版本：无原头像与手机流程

首页只保留批量截图入口，文件选择完成后自动处理，使用独立内置的小熊头像素材；无需原图或替换图输入。结果以手机双列卡片呈现，单张输出 PNG，多张输出 ZIP；详情中提供前后对照、放大滑动、取消或恢复、点击补框及折叠坐标校正。

默认 `right-layout` 检测流程使用量化主背景、前景区域、形态学闭运算与连通区域统计寻找右侧近方形头像。按共同列位置与尺寸选出头像列，通过列内逐行前景占用补齐截断头像，再用中段直边的颜色梯度细化边界。没有访问测试集原头像或网络模型；互不相同的头像也可按布局检测。参考 [OpenCV 官方连通区域统计](https://docs.opencv.org/4.13.0/d3/dc0/group__imgproc__shape.html)。

无源图时，圆角由每个角区相对局部背景的对比推断。可靠完整候选的估计半径取中值，截断头像也使用该半径；同一图采用相同像素半径。前端整图滑块与后端校验、导出均强制这一约束，不同截图独立估计。小尺寸手动框会约束整图半径上限为该框短边的一半。

这是针对聊天布局的视觉检测器，不能保证复杂壁纸、其他软件布局、空白头像和重度遮挡的表现。默认不处理左侧头像或聊天图片中的内嵌头像。原来的模板方式仍适用于明确给出 source 的开发用途，不参与默认手机上传流程。

前端经 Node 同源代理访问 Python API，避免真实手机通过跨端口直连而产生来源问题。默认只监听本机，显式 `start.ps1 -Lan` 才开放前端到局域网，后端保持本机监听；本机测试集接口对局域网客户端禁用。不包含公网身份认证或账号隔离。

本版验证：13 项自动测试通过；23 张真实截图识别 64 处右侧候选，含 3 处截断，全部截图内部半径一致，掩膜外差异为 0。候选数是回归观测，不是独立召回率证明。

## 验收标准

1. 默认覆盖右侧头像列、不同截图缩放、不同头像内容及部分可见头像；不依赖单一原头像或固定像素坐标。左侧和内嵌小图不属于默认范围。
2. 候选可审阅、关闭、补充及按原像素修改，避免把检测阈值当作隐私安全保证。
3. 替换图不拉伸：居中裁切并等比缩放；同图统一半径，支持小圆角、方角及人工指定圆形。
4. 输出无损 PNG，方向正确且无原图 EXIF；掩膜外像素逐值不变。
5. 全部本地处理，源文件不覆盖、不提交 Git；为输出附坐标和参数记录。

## 方法比较

| 方法 | 能解决的问题 | 在本项目中的取舍 |
| --- | --- | --- |
| UI 布局 + 连通区域 + 边界梯度 | 不提供原头像时，查找右侧头像列并统一合成 | 当前默认流程，CPU 运行。依赖清晰的聊天布局和较平坦背景，保留人工补选作为纠错入口。 |
| OpenCV 多尺度 NCC + 内部区域匹配 | 已知同一头像，缩放和 JPEG 压缩后的重复检索 | 兼容模式。CPU 可运行、可解释、无权重下载，容易建立像素回归检查。不能识别同人不同照片。 |
| SIFT / ORB + RANSAC | 旋转、透视和局部特征对应 | 小头像纹理不足时不稳定；本批截图没有明显透视，暂不增加默认链路。 |
| SuperPoint + LightGlue | 学习式局部特征匹配，提高复杂图像对的对应能力 | 作为未来复杂变形的候选定位器，需要另外评测；特征匹配结果仍需几何和圆角精修。 |
| SAM 3 / SAM 3.1 | 根据文本、示例或几何提示分割对象；3.1 改进多对象跟踪 | 官方实现需要较重的 PyTorch / CUDA 环境及模型访问。对数十像素 UI 头像和精确抗锯齿边缘并无现成保证，当前静态截图任务不值得引入。 |
| 自训小目标检测器 + 头像相似度检索 | 原头像缺失、多种 UI 风格、大量数据批处理 | 有真实标注与失败案例后再训练；本批 23 张相关截图不足以建立可靠泛化评估。 |

主流程的选择依据是任务约束和实际样本验证，并非宣称传统方法在所有情况优于神经网络。模型定位或分割也不直接等于最终合成边界。

## 为什么检测与合成分开

头像中间内容提供匹配信号，但圆角处同时包含旧头像、UI 背景和抗锯齿。直接复制矩形会覆盖圆角；简单把新头像 alpha-over 到旧头像，会在过渡像素保留旧图。圆角以 4× 子像素采样求像素覆盖率，且在局部背景足够平坦时按 `C = α × 新头像 + (1 − α) × 背景` 合成。

圆角估计在候选框角区比较原头像、截图与背景的重建残差，并在头像内部估计小幅颜色偏移。`edge_quality` 是启发式残差指标，不是统计概率。JPEG 的振铃及原头像与截图之间的重采样核差异仍会造成残差；低可信度边缘必须放大检查。

截断头像使用完整框决定缩放，用 `clip_h` 决定实际可修改区域，避免把遮挡后的输入栏当作头像的一部分。自动可见高度由逐行重建残差推断，遮挡线的混合像素仍可能有 1–2 px 误差，可手动修正。

## 前后端边界

前端独立监听 5178，原生 HTML / CSS / ES modules，无外部 CDN、字体、模型或分析脚本。后端监听 8000，通过限制本机来源的 CORS 提供 API；上传、预览和导出都走本机网络。API 返回原像素坐标，而不是浏览器显示坐标。解码后的任务图片存于内存；上传阶段框架可能使用系统临时文件，随请求结束关闭清理。限制文件数、像素数、解码总量及并发检测数。

主要接口：`POST /api/sessions` 上传检测，`POST /api/demo` 读取本机测试集，`GET .../images/{id}` 原图，`POST .../render` 应用当前校正，`POST .../export` 输出 ZIP，`DELETE /api/sessions/{id}` 清除。

## 验证与下一阶段

当前提供合成真值测试和真实样本回归。真实样本只报告检测候选、时间和掩膜外差异；当前没有独立人工像素级标注，不能计算可信的精确率、召回率或边界真值误差。

下一阶段应先收集原始 PNG 截图和独立人工标注：完整框、可见区域、角形状、遮挡、主题、缩放及“是否确为同一原头像”。按聊天会话、设备和原头像分组划分训练 / 验证 / 测试，防止重复聊天图泄漏。生成不同尺寸、裁切、圆角、重采样核及 JPEG 质量的合成数据，保留精确覆盖掩膜。

评估应分别记录：实例精确率 / 召回率、整张图仍有头像残留的比例、框 IoU、边界误差、合成过渡区误差、掩膜外改变数和 CPU 延迟。优先补齐上边 / 左右截断、单个严重遮挡头像、非均匀背景与圆形头像，再比较学习式检索或检测器是否带来可复现收益。只有在独立测试集证明收益后引入训练模型；最终仍保留几何精修与人工检查。
